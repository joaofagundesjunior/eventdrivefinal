# Relatório Final: Arquitetura Serverless e Orquestração de Pedidos

## 1. Escopo Técnico
Implementação de um pipeline de pedidos de pizza utilizando Google Cloud Workflows para orquestrar Cloud Functions (2ª Geração). A solução foca em desacoplamento, segurança via Secret Manager e resiliência com Pub/Sub (DLQ), tudo automatizado via Terraform.

## 2. Arquitetura e Componentes
*   Orquestração: Workflow 'pedidos-pizza' gerindo o ciclo de vida do pedido.
*   Segurança: Injeção de segredos (PAYMENT_API_KEY) diretamente via variáveis de ambiente protegidas pelo IAM.
*   Processamento: Cloud Functions em Python 3.10 para Reserva, Cobrança, Preparo e Envio.
*   Infraestrutura: 100% via Terraform, garantindo padronização e facilidade de deploy.

## 3. Evidências de Operação e Sucesso

### A. Resumo Financeiro e de Execução
O sistema processou múltiplos pedidos com sucesso, respeitando os fluxos de negócio e delays.
*   Montante Total Vendido: R$ 565,00
*   Estado Final das Execuções: Comprovado como SUCCEEDED em todas as ordens completas.

### B. Garantia de Idempotência (Evidência Crítica)
O sistema impede que um pedido seja cobrado duas vezes. O Workflow gera um UUID único no início de cada pedido e o envia como um cabeçalho de idempotência.

Logs de Evidência de Cobrança Única:
- Pedido idempotente-004: R$ 100,00 | Chave: ecad8404-dcb0-4393-983f-17b2d46f0235 | Status: Pago
- Pedido v3-003: R$ 225,50 | Chave: 8bb4ce2a-c3b8-4a9f-9629-641f1800ec3b | Status: Pago
- Pedido v2-002: R$ 150,00 | Chave: 688de664-5ed0-459e-99d1-3cf7f4df6fc2 | Status: Pago

### C. Segurança de Segredos
Logs confirmam que a função de pagamento acessou o segredo apenas quando autorizada pelo IAM.

## 4. Gestão de Erros (Resiliência)
Foi validado que falhas no input são capturadas imediatamente, resultando em STATE: FAILED e impedindo o processamento de dados inconsistentes.
